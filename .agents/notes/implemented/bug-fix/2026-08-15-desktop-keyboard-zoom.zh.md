# Agent Note：桌面壳负责有界键盘缩放

Status: implemented

[English](2026-08-15-desktop-keyboard-zoom.md) | 中文

## 问题

桌面窗口依赖 Chromium 与应用菜单处理键盘缩放，但应用菜单处于隐藏状态。在受影响的键盘布局上，`Ctrl` 加号不能放大，而 `Ctrl` 减号会继续缩小，使界面缩至无法通过对应快捷键恢复的程度。Chromium 还会按来源应用缩放值，因此重启以回环 Host 提供页面的桌面窗口后，仍可能恢复到不可用的缩放级别。

## 决策

桌面键盘缩放由 Electron 主进程负责。主进程的 `before-input-event` 监听器识别 `Ctrl` 或 `Command` 与 `+`/`=`、`-`/`_`、`0` 的组合，阻止 Chromium 另行处理快捷键，再通过 `WebContents.setZoomLevel()` 执行命令。

缩小在 -3 级停止，放大在 6 级停止；按照 Electron 的 `1.2 ^ level` 公式，缩放比例会保持在约 58% 至 299% 之间。零快捷键恢复为 0 级。回环页面完成加载后、隐藏窗口显示前，桌面壳也会恢复到 0 级，因此 Chromium 按来源保存的缩放值无法跨桌面应用重启延续。

快捷键解析与缩放计算位于不依赖 Electron 的模块中。主进程只提供键盘事件与 `WebContents` 操作，因此单元测试无需启动原生窗口，就能覆盖键盘布局解析后的加减号变体、两种桌面修饰键、复位、上下限和无关输入。

## 备选方案

- **依赖 Electron 菜单角色。** 缩放菜单角色提供标准快捷键，但桌面菜单处于隐藏状态，且报告所用键盘布局没有获得可用的放大路径。菜单角色也无法为已经不可用的同源缩放值提供重启复位机制。
- **在 Web 渲染器中处理快捷键。** 这会把桌面载体专有行为放进共享 Web 客户端，而且页面处理器可能晚于原生菜单快捷键运行。Electron 主进程能在页面键盘事件与菜单快捷键之前观察输入。
- **保留 Chromium 默认限制，只补 `Ctrl` 加号。** 这仍让恢复过程依赖已经表现不一致的实现路径，也不会在重启后清除按来源保存的缩放值。

## 影响

桌面缩放在受支持平台与键盘布局上的行为一致，在按键重复时仍保持可用，并提供两条恢复路径：按 `Ctrl`/`Command` 与 `0`，或重新打开应用。已识别的缩放快捷键不会传入 Web 页面。通过浏览器访问的客户端仍保留既有的浏览器缩放行为。

## 测试

桌面缩放单元测试覆盖 Control 与 `+`、`=` 的组合，Command 与 `+` 的组合，两种减号键值，上下限饱和、零复位、新窗口复位，以及必须保持未处理的输入。桌面 TypeScript 程序验证 Electron 事件与 `WebContents` 类型满足抽出的接口。
